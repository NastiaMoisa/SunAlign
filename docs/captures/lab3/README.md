# Первинні захоплення ЛР3

S1.vcd, S2.vcd і S3.vcd отримано з остаточної збірки src-2cbad8f6d7e5. Пілоти tim3/storage
мають інші збірки та негативні результати. Історичні записи ЛР2
у батьківському каталозі не є доказами ЛР3. run.vcd є робочим файлом
симулятора; його перейменовують лише після зупинки.

| Канал | Сигнал |
|---|---|
| D0 | PB8, SCL |
| D1 | PB9, SDA |
| D2 | PA2, UART TX |
| D3 | PA4, HIGH протягом пари ADC |
| D4 | PB0, вхід ZERO моделі, active LOW |
| D5 | PA5, LED |
| D6 | PA6, активний export до TX idle або Flash call |
| D7 | PA7, зміна рівня після прийняття ZERO |

VCD має базу 1 ns; точність зіставлення з UART обмежена його часовими мітками й серіалізацією. Аналізатор
зберігає переходи з початку симуляції, bufferSize=24000000. При S1
порівняно однакові 3005 завершених ADC інтервалів із UART та D3.
Межі UART-вікна й повної VCD-тривалості можуть відрізнятися.

analyze_lab3_vcd.py читає первинні фронти. Подія ZERO починається першим PB0
falling після не менше 30 ms HIGH і завершується наступною зміною PA7.
Наступні falling від брязкоту збережені окремо як stable_edge_ns. UART
sample-to-accept порівнюється за порядком лише при однаковій кількості подій.
Графік включає весь інтервал від першого фронту цієї події.
PA6 є об'єднаним маркером і не дає часу Flash при активному export.
plot_lab3_capture.py анотує отримані фронти без синтетичних сигналів.

startup/ містить 30 fresh Start/Stop. aux-checks.vcd містить NACK30, software reset30 і UART boundary8. fault-switches-normal.vcd має D5=AD0 та окрему схему fixture. GDB-paused записи не є running evidence. S3-attempt1 відхилений; деталі validation у metrics.
