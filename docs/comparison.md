Останній RES: MSP paint 600 B, heap 0, RX lost/errors/TX lost=0/0/0. ADC min/avg/max 96/99,999/105 мс (n=36055), MPU 97/100,073/210 мс (n=36027), dispatch 0/0,424/3 мс (n=245). Це HAL-ms статистика, а не чистий CPU WCET. ZERO/SAVE у S2 не стимулювались.

У 15Nov RTOS-контролі отримано BOOT, PANEL 4 мс, FIRST ADC7/IMU125 мс; UART з'єднання обірвалось, процес Code завершився з невстановленої причини. FATAL у цьому запуску не зафіксовано. У baseline hour capture тільки на другому пасивному аналізаторі від'єднано CAT0/CAT1; первинний аналізатор, MCU, ELF, входи й периферія незмінні. У RTOS-контролі CAT0/CAT1 ще були під'єднані. Годинні CPU-категорії та однакові повні S2 за цією парою не порівнюються. CAT-частки й основне порівняння належать парним коротким запускам 14Nov.

Окремий OS bench: context notification 54/54/54 мкс (n=100), ISR-task 58,35/58,4985/58,5 мкс (n=100). Це діагностичні ELF з тим самим ядром/портом, не виміри повної надійності продукту. Tick1000/100Hz у спільному вікні 50–450 мс: wrapper duty 8,01983125/1,11601875%; обидва повні S3 failed. Нульові sub-ms HAL counters не означають нульову вартість.

## Гіпотези ЛР3

1. Пріоритет panel зменшить пропуски й ZERO: Lab3 max32,3375 мс, 23689 panel skips; RTOS повний S3 failed. Початкове витіснення є, поліпшення продукту не підтверджено.
2. TX lost стане0: Lab3 S3 2489 B, RTOS IO зупинився. Нуль втрат не доведено.
3. Зменшиться MPU gap за30 reinit: Lab3 max211 мс; усі30 c підтверджено native RX і кластерами I2C ACK. RTOS отримав30 c без відповідей. Поліпшення не встановлено.
4. Flash erase перестане блокувати panel: Lab3 SAVE0/30, RTOS SAVE-фази не досягнув. Час успішного erase не встановлено. Host8296 interrupted cases перевіряють реальний storage adapter і CRC, не MCU readback.
5. Виростуть Flash/RAM: підтверджено +5320/+5352 B; task stacks2944 B всередині heap4800 B. Product post-flood snapshot used3864 B, але task-state неузгоджений; надійного S3 watermark немає.

У поточній реалізації придатнішим є суперцикл: він виконав перевірені часові цілі з меншими ресурсами. RTOS має інтеграційну відмову IO/task-state; коренева причина не ізольована. Це висновок щодо виміряної конфігурації, а не всіх можливих реалізацій FreeRTOS.

FR зі статусом failed: Lab3 FR13; FreeRTOS FR02–04 і FR06–14. FR01 підтверджено BOOT, FR05 — на host. Failed не означає verified або прийняття результату викладачем.
