# SunAlign: поточні результати ЛР3

Джерела `src-af2d5aa374d1`; досліджений ELF SHA-256 `9791f5375be0fea0e576c3d3c857ba3c16355593547e42675980834e502f8471`. Вимірювання виконано у Wokwi. Стійке збереження ZERO не підтверджено. Для коротких додаткових дослідів див. [boundary-drain](metrics/lab3/boundary-drain-20261101/README.md) і [профіль CPU](metrics/lab3/cpu-profile-20261101/README.md); свідчення S2 і S3 — у [каталозі результатів](metrics/lab3/current/). Діагностичні досліди нижче мають власні ELF-ідентифікатори.

- S1: 30,498 с MCU за UART, 305 інтервалів ADC, понад 30 тис. інтервалів panel; незалежний VCD. Окреме підтвердження положень повзунків не збережено.
- S2: один безперервний інтервал 3 600 000 мс MCU після GO, 7201 декодований PANEL у VCD, максимальний інтервал 501 мс. ADC 38 735 інтервалів: MCU 96000/99999/104000 мкс; VCD 96633,575/99997,896/103318,775 мкс. S2 TX lost=0, panel missed=773, stack watermark=584 B, heap=0. Статистика накопичувальна від старту.
- S3: 150498 мс MCU, 60 пар D4/D7 з D6 HIGH, max 31,979425 мс; у UART розпізнано 59 ZERO, наприкінці TX lost=301 B, panel missed=9102 та deadline misses=1403. Причину конкретної відсутньої UART-події не встановлено. D6 є об'єднанням експорту і Flash.
- `n` на 6500 мс викликала ERROR у PANEL 7000 і 7500 мс, до 8000 мс стан відновився; `c` на 15500 мс не була причиною цього відновлення. Це модельна відмова адреси, не утримання SDA. Окремий дослід SDA описано нижче.
- SDA stuck-low: у Wokwi з моделлю MPU6050 тестовий chip утримував SDA LOW від 5 до 10 с VCD; PANEL повідомляв ERROR до 10000 мс, перший CENTER/UNSET після звільнення — 10500 мс. За цей час VCD показав 50 ADC-маркерів, максимальний інтервал 100,639 мс. Окремий I2C timeout не виміряно.
- Старт з неготовим I2C-пристроєм: окрема мінімальна тестова модель за адресою 0x68 до 3 с дає NACK, потім ACK та статичний вектор 1 g. VCD показав три NACK до готовності та ACK після неї; FIRST adc 4000 мкс, FIRST imu 3106000 мкс, перший CENTER/UNSET 3500 мс. Це не реальна модель MPU чи перевірка живлення.
- UART навантаження з цільовими 2/5/10/20/40 запитами/с: фактична інтенсивність надсилання за host-часом 1,92/4,44/7,97/16,23/32,42 запиту/с. Останній повний RES біля PANEL 60000 мс показав нуль втрат RX/TX, але після нього повного фінального RES немає; першу частоту втрат не встановлено. VCD фіксує TX, але не RX.
- Окремий короткий boundary-drain: 8 с host на кожному рівні і 4 с без `d` до статистики. Фактичні швидкості 1,967 / 4,719 / 9,493 / 16,004 / 24,054 запитів/с; прирости TX lost відповідно 0 / 0 / 0 / 24003 / 74847 байтів, RX lost/errors залишилися нульовими. Перші спостережені втрати — після рівня 16,004 та паузи в цьому сценарії, точний поріг між рівнями невідомий. Усі шість рядків RES незалежно збіглися з UART TX з VCD, framing errors=0; VCD не містить RX. Новий `d` може перезапустити експорт.
- Три команди `s` після ZERO повернули `SAVE ... 0`; успішний запис/читання і power-cut не підтверджені.

Для S1–S3 SysTick має роздільність 1 мс, CPU load і субмілісекундний WCET недоступні. Окремий діагностичний ELF `src-b16af10ff4b0` у короткому Wokwi-профілі дав 44,309/44,370/44,878% min/avg/max позначених foreground-ділянок за 11 секунд VCD; це не повне навантаження ядра і не вимірювання S2 або S3. Сирі дані та межі методу наведено в [профілі CPU](metrics/lab3/cpu-profile-20261101/README.md). Статистика описує вибрані сценарії й не визначає верхньої межі для інших навантажень. Записані входи, команди і контрольні суми наведено в результатах відповідних сценаріїв.

Повторна незалежна Docker-збірка джерел `src-af2d5aa374d1` відтворила ELF/HEX/BIN побайтно; host-тести пройшли. Фактичні ресурси linker: Flash 23180 з 28672 B, RAM з резервами 6104 з 12288 B. Окремий build-current із робочих джерел дав ті самі hashes.

Статичні кадри для поточного ELF `9791f537…`: підтверджений LTO-асемблером шлях `main → serial_text → number → __io_putchar` має відомі кадри 344+24+56+8=432 B; watermark S3 — 640 B. Це не універсальна межа стека; деталі та найбільші ELF-символи — [stack-static-9791.json](metrics/lab3/current/stack-static-9791.json). Стару оцінку 456 B іншого ELF до цього образу не застосовують.

Додаткове коротке порівняння на іншому інструментованому ELF `src-b16af10ff4b0`: три 11-секундні вікна дали min/avg/max частки D6 HIGH 55,587/55,594/55,604%, 55,597/56,504/57,302% та 71,028/71,377/72,699%. ADC 32/32, нахил −31,41°. У кожному вікні D4 не мав спадів, отже третій профіль представляє експортне навантаження без підтверджених натискань ZERO. Позначені ділянки не є повним завантаженням CPU і не належать архівним S1/S2/S3.

Окремий FLASH_DIAG ELF `src-70dffc785c2c`: HAL erase для обох сторінок повернув 0, але скан після стирання знаходив по 512 нульових слів і жодного FF; запис тестового зразка пропущено, lock повернув 1. Першопричину не ізольовано, стійке збереження не підтверджено.
